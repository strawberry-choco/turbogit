# Operation is the dispatch unit; label text is display-only

`AppState::dispatch(op)` is the Shell's entry point for git work, and `op` is an
`Operation`: one value carrying the work, its display label, the roots it
affects, whether it changes a root's worktree set, and its identity. Settlement
runs on the completion event and matches an exhaustive `OpKind` — `Fetch`,
`Merge`, `Rebase`, `DeleteBranch`, `Shelve`, `WorktreeAdd`, `WorktreeRemove`,
`Other` — and never inspects label text. Adding a named variant without saying
how it settles is a compile error at the settlement site. The Git engine is
private to the app crate, so the Shell's two git interfaces are dispatch and a
value the app has already read or cached. The unit of work is a type, not a
sentence (ADR-0020).

## Considered options

- **An enum with a variant per rebase flavour** — rejected: standard, interactive and autosquash rebases would each need their own settlement arm, which is the original mistake wearing a type. `Rebase` carries a kind that produces the label wording and the plan; settlement matches `Rebase`, so a fourth flavour cannot miss the conflict hand-off.
- **Keep `run_git` as a label-taking alias for the display-only tail** — rejected: a two-faced interface. The long tail would stay free never to declare itself, and the same call would be both an operation and a string. The tail is `Operation::Custom`, which is greppable, so it stays visible instead of silently growing.
- **`trait Dispatch` with two implementors** — rejected: a seam standing in for a third mode that does not exist, and both modes are in-process. `Pump` is a named enum field.
- **Make `Operation: Clone` by boxing Custom's work as a re-runnable closure** — rejected: it buys cloneability by giving up the rule that justified `Custom`. Retry is `retry() -> Option<Operation>`; named variants rebuild from the plain data they carry, and a consumed `FnOnce` has nothing to rebuild from. Unretriable is then a property of the type rather than a match arm someone can write wrong.
- **Cache fills as Operations** — rejected: an operation earns its place by having identity, a label, an invalidation scope and a settlement arm; a cache fill has none of those, and inventing ten silent variants to satisfy a compiler is the empty-variant trap this rejects. Fills ride the same `Pump` through one internal read helper instead.

## Consequences

- **Settlement never reads prose.** The class of bug this removes: `"Interactive rebase"` and `"Autosquash rebase onto X"` both failed a `starts_with("Rebase ")` test, so completing them left the user mid-rebase with the conflict resolver never opening; `"Fetch · N repos"` failed an `== "Fetch"` comparison, so a multi-root fetch reported nothing while a single-root one reported. A reworded message can now change what a user reads but not what the app does.
- **An operation owns its invalidation scope.** Callers stopped constructing `Affected` by hand, and the helper that rebuilt one from an optional root is gone. Work for one root can no longer refresh another; where a site previously passed `Affected::All` because nothing was selected, the operation's own root now decides, and a site with no root selects nothing.
- **`OpKind` is what crosses the completion event**, because `dispatch` consumes the `Operation` to run its work. Do not "simplify" this by putting the `Operation` in the event: the event has to stay cheap, copyable and free of a live closure for its lifetime.
- **Toast Retry is unreachable by design.** The retry arms for Fetch, Pull and Push were deleted, not repaired: dispatch always forwarded an empty retry, so no production path could ever render the button, and `Toast` now carries no replay handle at all. Retrying is `Operation::retry` — a rebuilt operation dispatched like any other. Amended 2026-09-22: the Shelve confirmation does *not* call it — it dispatches a freshly constructed `Operation::shelve` (`ui/mod.rs:215`), and `retry` has no caller in any `src` file. What the sentence was pointing at still holds (retriable is a property of the named variants, not of `Custom`), but the method itself is dead and `.scratch/keyed-read/` deletes it. Re-adding a user-facing Retry button is a feature with its own ticket.
- **One dispatch entry point replaces three.** `run_git`, `run_git_with_retry` and the private worktree-dispatch sibling are deleted rather than kept as aliases. Worktree-mutating operations carry `mutates_worktrees()`, and `dispatch` posts the extra invalidation after the completion, which is the ordering ADR-0019 requires — so the rule no longer depends on which entry point a caller chose.
- **The Git engine is crate-private — for the adapters, not the port.** The rule "the Shell never calls git" is enforced by the crate boundary rather than asserted in documentation; no guard test greps for it. Amended 2026-09-22: that enforcement is partial, and the hole is exactly the size of `Operation::custom`. Its work closure receives `&dyn GitExecutor`, the UI crate depends on `turbogit-engine-api`, and 27 render-path closures in 11 UI modules use the reach — most of them wrapping a services call, several naming engine methods directly (`v.pull`, `v.tag_checkout`, `v.abort(root, "merge")`). What the boundary does close is `turbogit_engine`: the CLI and libgit2 adapters and `build_executor`. `.scratch/named-operations/` closes the rest by making `Custom` `pub(crate)`. Reads that are not cache-backed — is this branch merged, what is this tag's signing key, what would a dry-run push say — became named `AppState` methods, which is relocation, not a new abstraction; the same treatment is planned for the service-wrapping writes.
- **The borrowed-slice constraint is left violated on purpose.** Cache reads still hand back slices, so callers must not touch app state while holding one. Fixing it means owned handles per visible row, which is a frame-budget change under ADR-0014's virtualisation budget and belongs with the work that measures frame times. Amended 2026-09-22: that rested on owning *per visible row*, which ADR-0021 shows is not what is needed — an owned `Rc` handle per *frame* costs one refcount bump and leaves `&mut AppState` free to paint, and `diff_model()` already returns `Rc<DiffModel>` for exactly that reason.
- **The staleness rule is written eleven times** — five copies in the UI crate, six in the app crate — until a keyed-read slot unifies the diff, blame, pane-byte and granular-preview loads. This line originally said three. That slot is now ADR-0021 and `.scratch/keyed-read/`; it takes blame and the preview too.
- **The dispatch seam is internal.** `Pump` is chosen by constructor — `launch_in` selects `Spawned`, `for_roots` selects `Inline` — replacing the headless harness's half-applied synchronous-refresh flag, which dispatch ignored. Inline runs the work and posts into the existing channel rather than settling re-entrantly, so the caller drains exactly as production does. A test now dispatches, drains and asserts with no thread and no deadline.
- **Two pools stay threaded by decision.** `WorktreeLifecycle`'s admission slot and mutation epoch only mean something with a worker in front of them, and bulk fleet runs use the same pool; routing them inline would change the semantics ADR-0019 exists to protect for no test gain. The waits those suites keep are theirs, not the seam's.
- **ADR-0001 is untouched and narrowed.** This changes who may reach the engine seam and adds no new one — no executor is injected into the app state's constructor, and `GitExecutor` is not split into capability traits.
